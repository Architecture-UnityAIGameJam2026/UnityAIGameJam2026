# On Your Mark 협동 플레이 검증 기록

## HDRP 타이틀과 6글자 LAN 매칭

Unity 6000.3.28f1의 Multiplayer Play Mode에서 두 인스턴스를 열고 실제 타이틀 컨트롤로 검증했다.

| 조작 | 관찰한 결과 |
|---|---|
| GAME START → BACK | 기본 메뉴 세 줄이 왼쪽 화면 밖으로 이동했다. 같은 위치에 SINGLE PLAYER, MULTIPLAYER, BACK이 나타났고 BACK으로 원래 메뉴가 돌아왔다. |
| SINGLE PLAYER | 아레나로 한 번 이동해 선택한 파일럿과 AI 동료로 미션을 시작했다. |
| MULTIPLAYER → COPY | 원본 오른쪽 패널 위쪽에 내 6글자 코드가 표시됐고 COPY로 같은 값이 클립보드에 들어갔다. 방을 나갔다가 다시 열어도 같은 네트워크에서 코드로 대기할 수 있었다. |
| 잘못된 코드와 연결 실패 | 잘못된 입력은 타이틀에서 수정할 수 있었다. 유효한 형식이지만 응답하지 않는 주소에 접속한 뒤에도 타이틀이 자기 방을 다시 열었고 이후 참가자를 받았다. |
| 상대 코드 입력 → JOIN | 참가자가 아래 칸에 코드를 입력한 채 기다리는 동안 두 인스턴스 모두 타이틀에 머물렀다. JOIN을 누르자 각자 아레나를 한 번 로드하고 같은 첫 미션에 들어갔다. 양쪽 모두 검을 선호한 경우 방장은 검, 참가자는 레일건을 맡았다. |

PlayMode 테스트 14개가 모두 통과했다. 여기에는 코드 패널의 컨트롤과 글자 수 제한, GAME START와 BACK의 화면 전환 검사가 포함된다. Windows x64 실행본도 두 개 띄워 같은 6글자 코드로 접속했다. 양쪽 로그에서 P1 검은 호스트, P2 레일건은 참가자가 소유한 것을 확인했다. 멀티 접속 검증에는 한 PC의 실제 Wi-Fi 주소를 사용했다. 서로 다른 물리 PC 두 대 사이의 방화벽과 공유기 설정은 검증 범위 밖이다.

## HDRP 협동 미션 검증 (타이틀 매칭 개편 전)

Windows의 Unity 6000.3.28f1, Multiplayer Play Mode의 `TwoPlayers`에서 호스트와 클라이언트를 각각 실행했다. 두 에디터 모두 `Assets/OYM/Scenes/MainTitle.unity`에서 시작한다. GAME START로 호스트를 열고 CO-OP의 방 코드로 참가하면 `Assets/_Project/Scenes/Arena.unity`에서 같은 미션을 진행한다.

| 검사 | 확인한 결과 |
|---|---|
| 접속과 무전 | 혼자 연 방에 AI 동료와 청록색 중재자가 등장했다. 첫 관제 무전의 녹음과 자막이 재생됐고 다른 에디터가 AI의 자리를 이어받았다. 녹음 333개와 임무 경로의 NavMesh 지점 27개가 로드됐다. |
| 스폰과 전투 | 두 플레이어가 HDRP 시작 선체에 HP 100으로 스폰됐고 조준점은 각각 하나였다. 검 클릭은 40 피해를 주고 노란 상자를 표시하지 않았다. 총 클릭은 40발에서 39발로 차감됐다. |
| 잔해 사이 도약 | 두 역할 모두 첫 선체 가장자리에서 W와 Space로 11.69m 간격을 건너 실제 다음 메시 위에 착지했다. 단독 점프 높이는 P1 2.20m, P2 1.50m였다. |
| 폭발 피해 | 같은 거리에서 엄폐 시 HP 100, 노출 시 65였다. 대상에 충돌체 두 개를 붙여도 한 번만 피해를 받았고 피격 비네트가 나타났다. |
| 협동 구간 | 첫 방어에서 P1이 놓친 파편은 P2에게 35 피해를 줬다. 분기점에서 HUD 및 스킬 권한이 교차했고, 동시 그로기는 해당 페이즈의 체크포인트로 돌아갔다. 착지 링을 놓치면 두 역할 모두 다시 시도할 수 있었다. |
| 관전과 엔딩 | 그로기 중 C로 동료 1인칭 카메라에 진입했다. 다음 구간에서 HP 50으로 복귀했다. 마지막 연계 후 중재자 음성이 멈췄고 두 에디터에 MISSION CLEAR가 표시됐다. 호스트의 복귀 입력으로 양쪽 모두 타이틀을 로드했다. |

두 명이 서 있을 때의 검 입력, P1 그로기일 때의 P1 스킬 입력과 P2 궁극기 발동, P2 그로기일 때의 P2 스킬 입력과 P1 마무리를 같은 체크포인트에서 반복했다. 별도 솔로 실행에서는 P1 AI가 시작 잔해부터 위쪽 선체와 상갑판까지 직접 점프·호버해 마지막 연계에 도달했다. 이때 사람 역할의 이동·타이밍과 적 처치는 자동화했다.

Jev 선택기는 로컬 HTTP 응답으로 검증했다. 상태와 대사 후보를 보낸 뒤 선택 ID `heal_crit`, 초점 대상 `melee`, 신뢰도 `0.91`을 해석했다.

같은 버전을 로컬 `main`에 적용하고 락온 조준점과 자막 PlayMode 테스트 12개를 다시 실행했다. 12개 모두 통과했다. Windows x64 빌드도 성공했다. 독립 실행 파일 두 개를 같은 PC에서 실행해 P1 호스트가 P2 클라이언트를 관측하고, P2 클라이언트가 자신의 파일럿을 인계받는 것까지 확인했다. 전체 미션은 위의 두 에디터로 검사했다.

무기와 타이밍 링은 Input System 이벤트로 조작했다. 긴 구간 이동은 체크포인트로 옮기고 웨이브 적은 서버 피해 판정으로 처치해 전환을 반복했다. 외부 Jev와 ElevenLabs 서비스에는 요청을 보내지 않았다. 네트워크는 같은 PC의 루프백 연결을 사용했다.

## 프로토타입 P12 당시 검증 환경

테스트 환경: Unity 6000.3.28f1, macOS (Apple M1), Netcode for GameObjects 2.14.
에디터 테스트는 Multiplayer Play Mode 시나리오 `TwoPlayers` (메인 에디터 + 가상 플레이어 1),
빌드 테스트는 같은 Mac에서 Development 빌드 두 개를 띄워 진행했다.

## 1. 빌드를 바로 접속시켜 테스트하기

실행 인자로 접속과 포지션 선택을 자동으로 할 수 있다.

| 인자 | 동작 |
|---|---|
| `-host` | 바로 Host 시작 |
| `-join <IP>` | 그 주소로 바로 Join |
| `-role 0` / `-role 1` | 포지션 팝업이 뜨면 P1 Sword / P2 Railgun 자동 선택 |

```bash
# 같은 Mac에서 두 개 띄우기
open -n Builds/OnYourMark.app --args -screen-fullscreen 0 -screen-width 960 -screen-height 540 -host -role 0
open -n Builds/OnYourMark.app --args -screen-fullscreen 0 -screen-width 960 -screen-height 540 -join 127.0.0.1 -role 1
```

주요 이벤트는 Player.log에 `[OnYourMark]`로 남는다 (접속 / 스폰 / 웨이브 시작 / 라운드 종료 / 끊김).
Mac 로그 위치: `~/Library/Logs/DefaultCompany/OnYourMark/Player.log`

## 2. 다른 PC와 연결이 안 될 때

1. Host 쪽 포지션 선택 화면 아래 `Partner joins: x.x.x.x`에 나온 주소로 Join한다.
2. Host 컴퓨터 방화벽에서 게임을 허용한다 (Mac: 시스템 설정 > 네트워크 > 방화벽, Windows: Defender 방화벽 허용 창에서 개인/공용 모두 체크).
3. 학교·행사장 Wi-Fi는 기기끼리 통신을 막는 경우가 많다. Host가 `ping <상대 IP>`에 응답을 못 받으면 휴대폰 핫스팟 하나에 둘 다 연결한다.
4. 접속 실패는 약 10초 안에 "Could not reach ..." 안내로 표시된다 (기존 기본값은 약 60초).

사람이 마우스로 직접 조준해 맞히는 것은 해 보지 않았다. 미션 클리어는 마지막 웨이브 클리어 이벤트를 직접 보내 확인했다.

## 4. P12에서 바꾼 것

- 웨이브 적을 0.6초 간격으로 한 마리씩 내보냄 (`WaveData.spawnInterval`). 가만히 있어도 웨이브 1은 버티고 웨이브 2에서 쓰러짐.
- P1 검기를 가득(4칸) 찬 상태로 시작 (`P1_Sword.resourceStartsFull`). 시작부터 소모품 자동 요청이 켜져 P2 좌클릭이 지원으로 바뀌던 문제 해결.
- 접속 실패 판정 약 60초 -> 약 10초, 실패 원인 안내 문구.
- Host 화면에 자기 LAN 주소 표시.
- 실행 인자(-host / -join / -role)와 `[OnYourMark]` 로그.

## 5. 남은 이슈 / 확인 필요

| 구분 | 내용 |
|---|---|
| 미검증 | 실제 PC 두 대 LAN 접속 (테스트한 Wi-Fi에서 상대 기기 ping이 막혀 있었음) |
| 미검증 | 마우스로 직접 조준, 빈 총 격발음 실제 재생 |
| 기획 확인 | 지도 각성 발동 키를 F로 정함 (기획서에 없음) |
| 기획 확인 | 소프트 락온은 조준선 1.5m 이내 판정만 있음 (조준점이 끌려가는 흡착 없음) |
| 기획 확인 | 폭발탄이 공중 Hover에 맞으면 5.5m 위에서 터져 지상 적까지 닿지 않음 |
| 기획 확인 | Hover는 거리를 유지하므로 처치하지 않으면 웨이브가 끝나지 않음 |
| UI | 모든 문구가 영어 (TMP 기본 폰트에 한글 없음, 한글 폰트 에셋 추가 필요) |
| 빌드 | 서명 안 된 앱이라 다른 Mac에서는 우클릭 > 열기로 실행, 첫 실행 시 네트워크 허용 필요 |
| 프로젝트 | `ProjectSettings.asset` 전체화면 모드 변경은 커밋하지 않음 (작업자 확인 필요) |

## 6. HDRP 아레나 협동 회귀 검증 (4페이즈 및 AI 동료 통합 전)

Windows에서 Unity 6000.3.28f1의 `TwoPlayers`로 호스트와 참가자를 실행했다. 시작 씬은 `Assets/OYM/Scenes/MainTitle.unity`, 플레이 씬은 `Assets/_Project/Scenes/Arena.unity`다.

| 확인한 동작 | 결과 |
|---|---|
| 타이틀에서 호스트 방 생성, 잘못된 코드 입력 후 유효한 코드로 참가 | 두 플레이어가 서로 다른 역할로 스폰되고 웨이브 1 진입 |
| 파츠 교환 및 오버차지 | 선택창의 자원·스킬 아이콘이 탄약·번개로 표시됨. 양쪽에서 자원 교환이 반영되고 파트너 탄약에 `60/40` 표시 |
| 웨이브 1에서 참가자 퇴장 | 수정 전에는 호스트가 두 역할이 점유된 채 전투에 남았다. 수정 후에는 `PARTNER DISCONNECTED`가 표시되고 웨이브가 멈춤 |
| 호스트가 `RESTART`를 누르고 참가자가 같은 방에 재접속 | 두 역할 슬롯과 교환 상태가 초기화되고, 서로 이전과 반대 역할로 스폰 |
| 재접속 후 웨이브 1~3 완료 | 호스트와 참가자 모두 세 웨이브를 거쳐 `MISSION CLEAR` 표시 |

메뉴와 HUD 동작은 코드로 호출했다. 웨이브 검증은 호스트에서 스폰된 적에게 피해를 주어 처치했고, 다음 웨이브와 결과 화면은 게임 로직으로 진행됐다. 별도 PC 간 LAN과 독립 실행 빌드는 이번 검증 범위에서 제외했다.

## Jev 팀 무전 확인

- 호스트가 역할을 고르면 5초 후 AI가 빈자리를 채운다. B를 누르면 바로 시작한다. 다른 사람이 접속하면 AI가 맡았던 역할을 이어받고 중재자가 계속 두 사람과 대화한다.
- 아무 말 없이 웨이브에 진입하거나 탄창을 비워 선제 무전을 확인한다. 호스트는 기본 6초 주기로 상황을 평가하며, 다운·탄약 고갈·지원 요청·HUD 교환·위협 감지 등은 다음 주기를 기다리지 않고 판단을 요청한다. Jev는 침묵을 선택할 수 있다.
- 혼자 P2 Railgun을 골라 첫 웨이브를 시작하고 직접 쏘지 않는다. 근거리 동료가 지상 적을 추격해 참격을 하는지 확인한다. P1 Sword를 고르면 원거리 동료가 사격하고 빈 탄창을 자동으로 재장전한다. 두 역할 모두 쓰러진 파트너에게 접근해 소생한다. 이 행동은 무전과 독립적으로 동작한다.
- V를 누른 채 한국어나 영어로 말한 뒤 놓는다(최대 6초). 호스트에서 ElevenLabs Scribe로 인식하고 Jev가 응답을 선택한다. 원거리 동료가 몇 발 쏜 뒤 탄창이 남아 있을 때 재장전을 요청하면, 수락 대사와 실제 재장전을 함께 확인할 수 있다. 영어 음성과 한국어·영어 자막을 사용한다.
- 호스트 키 파일은 로컬 JevSettings에 경로를 지정하거나 게임 실행 전에 `OPENROUTER_KEY_FILE`, `ELEVENLABS_KEY_FILE` 환경 변수로 지정한다. 클라이언트는 호스트를 통해 음성을 인식한다. V로 전송한 음성은 ElevenLabs로, 인식 문장과 상황은 OpenRouter로 전송된다.
- 대사·자막·발화 조건은 `Assets/_Project/Resources/VoicePresets/lines.csv`, 행동과 대사의 대응표는 같은 폴더의 `actions.json`에 있다. Arena의 CalloutDirector에서 기본 판단 주기와 발화 간격을 조정할 수 있다.

### 솔로 동료의 전투 상태와 전환

호스트가 빈 역할의 동료를 제어한다. 동료는 0.35초마다 표적과 지원 요청을 확인하며, 매 프레임 소생·무전 지시·전투 순으로 다음 상태를 결정한다. 지원과 재장전은 이동 중에도 가능하다. 현재 상태와 표적은 무전 판단에 전달하는 `RadioCompanion.Status`에서 확인할 수 있다.

| 상황 | 상태 | 이동과 종료 조건 |
|---|---|---|
| 자신이 다운되거나 파트너가 없음 | Inactive | 이동과 상호작용을 중단한다. |
| 파트너 다운 | ApproachDownedPartner → Revive | 쓰러진 위치로 접근하고 소생 거리 안에서 멈춰 상호작용을 유지한다. 파트너가 일어나면 다시 상황을 판단한다. |
| 합류 지시 수락 | Regroup | 수락 순간 파트너가 있던 지점을 한 번 저장한다. 1.5m 이내 도착 또는 15초 경과 시 지시를 해제한다. |
| 대기·조준·엄폐·대시·단말기 지시 | Hold / TakeCover / Dash / UseTerminal | 지시의 위치와 기한을 사용한다. 대기·조준·엄폐 중에는 사선에 들어온 적을 공격할 수 있다. |
| 지상 적을 상대하는 근거리 동료 | Pursue → MeleeAttack | 적에게 접근해 참격하고, 사거리를 벗어나거나 시야가 막히면 다시 추격한다. |
| 원거리 동료 또는 검기를 쓸 수 있는 근거리 동료 | FindFiringLane → Fire | 사거리가 부족하거나 시야가 막히면 적 주변에서 도달 가능하고 시야가 열린 지점을 찾는다. 사선이 확보되면 그 자리에서 사격한다. |
| 원거리 동료에게 적이 접근 | Withdraw | 8m 안으로 접근하면 이탈한다. 같은 상태에서는 11m까지 거리를 벌려 경계에서 전진과 후퇴를 반복하는 현상을 줄인다. |
| 원거리 탄창 소진 | Reload | 재장전한다. 가까운 위협 때문에 이탈해야 하면 이동 중에도 재장전을 계속한다. |
| 교전할 수 있는 적과 지시가 없음 | Guard | 활성 미션에서는 자신의 다음 목표로 이동한다. 목표가 없는 상태에서는 현재 위치를 경계한다. |

확인할 때는 두 역할로 각각 시작한다. 각 페이즈 사이에 동료가 자기 목표로 움직이는지 보고, “이리 와”를 말해 합류가 수락되면 바로 다른 방향으로 이동한다. 동료는 호출한 지점에서 멈춰야 한다. 원거리 동료가 사격 중일 때도 플레이어 혼자 자리를 옮겨 사선을 유지하는지 확인한다.

청록색 중재자는 처음에 두 캐릭터의 중간 지점에 뜬다. 중재자가 발언하면 호스트가 그 순간의 대화 위치를 보내고, 중재자는 그 지점으로 이동해 대기한다.
