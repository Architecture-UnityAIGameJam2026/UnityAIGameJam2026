## 파일 간 연결 규약

- **대사 카탈로그 `lines.csv`** — 기존 형식의 `id, file, english, korean, category, tone, seconds`를 유지한다. 추가 열은 `speaker, recipient, trigger_en, implementation_status, tts_tags, action_id, actor_ref, target_ref, speech_phase`로 한다. `file`은 납품 폴더 기준 상대 경로, `seconds`는 후처리한 파일의 실제 길이다. `english`와 `korean`을 같은 ID의 두 자막으로 사용한다.
- **합성 입력과 Jev 입력** — ElevenLabs에는 감정 태그와 영어 대사를 함께 보낸다. 예를 들어 합성 입력이 `[tense] Reloading. Cover me.`라면 Jev와 영어 자막은 `Reloading. Cover me.`를 사용하고 한국어 자막은 “재장전 중이야. 엄호해 줘.”로 연결한다. Jev에는 현재 상태에서 유효한 후보의 ID, 영어 원문, 영어 발화 조건, 발화자·수신자를 전달한다.
- **행동 정의표 `actions.json`** — 20개 행동을 ID로 관리한다. 대사가 행동에 연결되면 카탈로그의 `action_id`가 이 표의 ID를 가리킨다. 모든 행동에 대응하는 대사를 최소 1개 둔다. 상황 안내와 감사 인사는 행동 ID를 비워 둔다.
- **행동과 음성의 타이밍** — 예를 들어 “Reloading.”은 재장전 시작에, “Fresh mag.”는 같은 행동의 성공에 연결한다. 제어 AI가 P2에게 지시할 때는 발화자가 제어 AI이고 실행자는 P2다. 완료 보고와 미리 듣기는 행동을 다시 실행하지 않는다. 사람 플레이어에게 보낸 지시는 안내로 전달하고, 자동 실행은 권한 있는 AI에 한정한다.
- **키 전달** — 제작자가 지정한 로컬 ElevenLabs 키 파일을 API 인증에만 사용한다. 비밀 값은 대본·카탈로그·로그·저장소·납품 패키지에 기록하지 않는다.

## 인수 체크리스트

- [ ] 역할별 고유 대사와 최종 WAV가 각각 100개이고, 300개 ID 모두 영어 원문과 한국어 자막으로 조회된다.
- [ ] 영어 자막이 실제 발화와 일치하고 Jev 입력에 감정 태그나 효과음 지시문이 섞이지 않는다.
- [ ] 20개 행동이 모두 유효한 대사 ID에 연결된다. 지시자와 실행자가 다른 사례, 행동 취소, 완료 보고, 적합한 대사가 없어 `none`인 사례를 검수한다.
- [ ] 무전 노이즈와 기계음이 최종 WAV에서 들리고, 첫 단어·끝음절·표적명·경고어가 효과에 묻히지 않는다.
- [ ] 납품 기록에 기준 메인 커밋, 사용 모델, 역할별 보이스, 오디오 포맷, 검수 결과, Unity에서 연결할 이벤트를 남긴다. 이번 작업의 범위는 음성 자산과 행동 정의·매핑까지다.
